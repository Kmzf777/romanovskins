3 Abordagens para Completar o MVP

Qual sequência faz mais sentido para chegar ao ar com qualidade?

A

Abordagem Cirúrgica

Consertar apenas os 9 bugs críticos identificados — nada mais, nada menos. Cada fix é isolado, testável e não quebra nada adjacente.

✅ Prós
  • Mais rápido de entregar
  • Menor risco de introduzir novos bugs
  • Scope bem delimitado
⚠️ Contras
  • Ainda vai precisar de um segundo sprint logo em seguida
  • UX ainda fraca no checkout (sem timer)
Escopo: Fix bugs críticos + pg_cron + sorteio Loteria Federal no admin
B

MVP Completo ⭐ Recomendado

Bugs críticos + 3 UX essenciais que qualquer concorrente já tem: timer no checkout, progresso de cotas, e "meus tickets". Não são extras — são esperados pelo usuário.

✅ Prós
  • Site chega ao ar já competitivo
  • Timer evita abandono no checkout
  • Progresso cria senso de urgência (converte mais)
  • Sem segunda sprint logo em seguida
⚠️ Contras
  • Leva ~30% mais tempo que a opção A
Escopo: Fix bugs + pg_cron + sorteio + timer checkout + barra de progresso + página "meus tickets"
C

MVP + Realtime

Tudo da opção B, mais atualização em tempo real do grid de tickets via Supabase Realtime — quando alguém compra, todos veem na hora.

✅ Prós
  • Feature premium que poucos concorrentes têm
  • Cria senso de urgência real ("alguém acabou de comprar!")
⚠️ Contras
  • Adiciona complexidade de websocket/subscription
  • Pode ser adicionado depois sem impacto no resto
  • Mais tempo de entrega
Escopo: Tudo da B + Supabase Realtime no TicketGrid
